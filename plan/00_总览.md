## 2. 系统分层（与 PDR-001 §4 对齐）

```
第0层 宪法          → constitution.yaml（自然语言不变量 15 条）+ judge 可引用
第1层 Spec          → spec_repo：L1/L2/L3 三层条款、稳定ID、条款摘要、R级、don't-care 区
第2层 Oracle        → oracle 目录：holdout 场景库 + 语料生成器 + 基线契约面 + rubric（对 builder 不可见）
第3层 Instance      → builder fan-out 产物（staging/ 下，可丢弃）
第4层 World         → 已准入代码库（world/ 下，携带 EVIDENCE.json + 账本）
```

物理实现一律遵守：`Admit = H1..H8 全 PASS ∧ judge 不否决`；`inconclusive/error 一律不准入`。

## 4. 里程碑（PDR-001 §12 迁移梯度，附可验收门槛）

| 阶段 | 目标 | 门槛（全为机械化可测） |
|---|---|---|
| M0 收割 | spec 仓建立、目标域 spec 收割、H1–H4+H7 上线 | `ci/run_all_gates.sh` 全绿；锚点扫描对收割域 0 孤儿 0 陈旧 |
| M1 锚定 | holdout 场景库达阈值、H5 差分门可用、R 级注册表上线 | 目标域每 L1/L2 条款 ≥1 硬见证（witness_coverage=1.0）；差分引擎对 fixtures 判定正确 |
| M2 再生 | R0/R1 常规 fan-out；judge 校准上线 | 连续 3 波次零逃逸；judge kappa ≥0.6（对标注集） |
| M3 工厂 | R0/R1 默认再生、R2 演进、R3 冻结；deep agent 提案通道 | 健康度快照各指标进入阈值带；降级触发器全部有测试覆盖 |

不得跨阶段。在 oracle 覆盖率不足的域宣布"代码可丢弃"是本范式唯一致命误用（PDR-001 §12）。

## 6. 全局铁律（执行 agent 必读）

1. 契约改动 = 规则变更提案，任何团队不得私改 `swarm_kernel/contracts/`；需要改时走 RuleProposal → 人类批准 → 新 session 生效。
2. 门禁判定只认退出码与 GateResult：0=pass，1=fail，2=inconclusive/error；`inconclusive` 永远不准入。
3. builder 产物必须带：`swarm_entry.py`（适配器）、`contract.json`（契约面）、`report.json`(资源报告)、L1/L2 条款锚点注释。缺任何一项 = 对应门禁 inconclusive 或 fail。
4. holdout 场景、rubric、语料生成器存放在 oracle 目录，builder 工作区 ACL 拒绝读取；测试 builder 侧功能一律用 mock 场景集。
5. CI 永不写黄金输出；黄金更新必须人类批准 + 附 manifest（版本/种子/配置哈希/批准人）。
6. 判别侧（judge/spec moderator）与生成侧（builder）不得同一 session 上下文；judge 档位 ≥ builder 档位。
7. 所有跨组件消息走 ContractEnvelope（带封条哈希与保密级）；绕过总线直传 = 违反隔离纪律，测试会失败。

## 7. 验收方式

- 内核回归：`cd swarm-kernel && python -m pytest tests -q`（86 用例全绿）
- 门禁演示：`./ci/run_all_gates.sh`（good 过、bad/secret/drift 挡，退出码语义正确）
- 阶段验收：按 08 文档 checklist 逐项机械化勾选。
