# 第一部分：自适应Fan-out策略与动态N值（01）

> 来源文件：`01_adaptive_fanout_papers.md`（30条）。评分：A=23，B=7，C=0。

## 一、自适应 Fan-out / 动态 N 值选择（采样与分支）

#### 1. Best-of-∞: Asymptotic Performance of Test-Time LLM Ensembling [A]
- **总结**：分析多数投票下 best-of-N 的 N→∞ 极限，因无限预算现实中不可行，提出按"答案一致性"自适应选择 N 的生成方案，把推理计算高效分配到真正需要更多采样的样本上；并扩展为多 LLM 加权集成，最优权重用混合整数线性规划（MILP）求解，混集可击败任何单模型。
- **评分理由**：直接回答子问题(1)，给出"答案一致性作为自适应N信号"的可落地方案，并有集成路由衍生价值。

#### 2. AdaBoN: Adaptive Best-of-N Alignment [A]
- **总结**：两阶段、prompt 自适应的预算分配算法：第一阶段小探索预算估计每个 prompt 的奖励分布，第二阶段据此把剩余采样预算按需分配。在 12 组 LM/RM 组合、50 批 prompt 上，相同预算下优于均匀分配，等同于"预算放大 20% 的均匀分配"，批次越大优势越明显。
- **评分理由**：直接解决子问题(1)，量化收益明确（等价节省约 20% 预算），实现成本低、可落地。

#### 3. Adaptive Rectification Sampling for Test-Time Compute Scaling (AR-Sampling) [B]
- **总结**：用过程奖励模型（PRM）作为验证器，配合触发句，引导 LLM 在合适步骤做更细粒度自修正，避免对已正确推理链浪费 token。在 GSM8K 与 MATH500 上提升准确率并只生成"合理数量"额外 token。
- **评分理由**：与子问题(1)相关（自适应控制推理开销），但侧重单链自修正而非并行 fan-out，需改造后用于 N 值决策。

#### 4. Interpretable Adaptive Sampling for LLM Test-Time Scaling [A]
- **总结**：用轻量模糊控制器把人可解释信号（prompt 复杂度、模型置信度、熵）映射为每个查询的整数采样预算：易/高置信少采样、难/低置信多采样，使推理期计算可被检查。在公平对齐协议下，多模型多数据集上超过若干标准基线，并在接近全预算控制的同时降低平均采样数。
- **评分理由**：直接、完整回答子问题(1)，可解释的分级控制器方法轻量可落地，并明确降低平均采样数。

#### 5. Strategic Scaling of Test-Time Compute: A Bandit Learning Approach [A]
- **总结**：把跨查询测试时算力分配建模为 bandit 学习问题，在线估计查询难度并分配计算：难题多算、易题少算，还可在难题中优先"可解"实例。实证在 MATH-500 提升最高 11.10%、AIME25 最高 10.82%、LiveCodeBench 最高 11.23%（均相对基线）。
- **评分理由**：直接回答子问题(1)，给出可实时执行的 bandit 自适应分配，收益数字明确（约 11–16% 相对提升）。

#### 6. Uncertainty-Aware Budget Allocation for Adaptive Test-Time Reasoning (UAB) [A]
- **总结**：凹整数优化框架，在固定预算下按每问题不确定度再分配：Phase 1 每问生成一个样本，用平均负对数似然（ANLL）作零额外成本难度信号并参与投票；Phase 2 用边际贪心精确求解凹覆盖最大化代理，把剩余预算分给高不确定问题。在 6 个模型、5 个基准上平均准确率最高 +3%、单基准最高 +5%，低资源场景增益最大。
- **评分理由**：直接回答子问题(1)，零额外推理成本、无需辅助模型即可动态分配预算，方法简单、收益清晰。

#### 7. Parallelism Meets Adaptiveness: Scalable Documents Understanding in Multi-Agent LLM Systems [B]
- **总结**：文档理解多 Agent 系统协调框架，融合动态任务路由、双向反馈与并行 Agent 评估：Agent 依据置信度与负载重分配任务，在高模糊子任务上"竞争"并行多个 Agent、由评估器挑选最优。相对静态与部分自适应基线有实质提升，但未给出明确 token/成本量化。
- **评分理由**：涉及多 Agent 并行+评估器选优，与子问题(1)相关，但缺量化收益且为文档领域特定场景，需抽象改造。

## 二、基于不确定性的 Token / 计算分配

#### 8. A Survey of Test-Time Compute: From Intuitive Inference to Deliberate Reasoning [B]
- **总结**：系统综述测试时计算（TTC）扩展，沿 System-1→System-2 脉络梳理重复采样、自修正、树搜索等方法，是理解自适应算力分配的背景性综述，本身不提供新方法与量化收益。
- **评分理由**：作为基线综述厘清 TTC 全景，为子问题提供概念框架，但无落地方法与收益数字。

#### 9. SelfBudgeter: Adaptive Token Allocation for Efficient LLM Reasoning [A]
- **总结**：训练模型自估计每个查询所需推理预算，再用预算引导的 GRPO 做强化学习，在保持精度同时按难度动态压缩输出长度。数学推理任务平均响应长度压缩 61% 且精度保持；用户可事先看到预计时长决定继续或停止。
- **评分理由**：直接回答子问题(1)（token 预算按难度自适应），61% 长度压缩收益显著，可落地到 Agent 推理链。

#### 10. EAGER: Entropy-Aware GEneRation for Adaptive Inference-Time Scaling [A]
- **总结**：免训练方法，基于 token 级熵分布感知不确定度，仅在高熵 token 处分支到多条推理路径，并把节省的预算重分配给最需探索的实例。RLVR 场景 Pass@k 最高 +37%、token 减少 59%；测试时场景较全并行采样 Pass@k +12%、token 减少 64%。
- **评分理由**：直接解决子问题(1)（熵驱动分支控制 N 与 token），量化收益突出（token 减少过半），免训练可落地。

#### 11. Learning When to Sample: Confidence-Aware Selective Sampling for Reasoning [A]
- **总结**：置信度感知选择性采样框架，推理时仅分析单一轨迹，用轨迹级数值特征与句子级语言特征自适应判定"依赖该轨迹即可还是触发多路径采样"。精度相对基线仅降 -0.41±0.58 与 -0.31±0.58 个百分点，却分别减少 token 71.7±5.0% 与 36.6±9.1%。
- **评分理由**：直接回答子问题(1)，单轨迹即可决定是否扩采样，token 节省（36–72%）显著，可落地可迁移。

#### 12. Seer Self-Consistency: Advance Budget Estimation for Adaptive Test-Time Scaling (SeerSC) [A]
- **总结**：融合 System1 与 System2：先用快速 System1 计算查询答案熵作为预算估计信号，再据此在 System2 下做动态自一致性，并借提前准确估计实现并行生成降低延迟。较现有方法在无明显性能损失下，token 消耗最高降 47%、推理延迟最高降 43%。
- **评分理由**：直接回答子问题(1)（用 System1 熵提前定预算），同时给出 token 与延迟双降的量化收益。

#### 13. Adaptive Test-Time Compute Allocation for Reasoning LLMs via Constrained Policy Optimization [A]
- **总结**：把算力分配形式化为"平均预算约束下最大化准确率"的约束优化，两阶段 Solve-then-Learn：求解阶段经拉格朗日松弛分解为带闭式最优动作的逐实例子问题，成本随对偶变量单调、可用二分搜索精确对齐预算；学习阶段训练轻量分类器预测 oracle 动作以便实时部署。在 MATH/GSM8K 与三个 LLM 上，匹配预算下最高提升 12.8% 相对准确率，模仿准确率超 91%。
- **评分理由**：直接、严格回答子问题(1)，有理论保证+可落地轻量分类器，量化收益明确。

#### 14. DynScaling: Efficient Verifier-free Inference Scaling via Dynamic and Integrated Sampling [A]
- **总结**：两大创新：一是集成式并行-顺序采样（从初始独立并行响应构造合成顺序推理链，兼顾多样性与连贯性）；二是 bandit 动态预算分配（依据已采样响应的不确定度把推理预算分配到各查询）。无需外部验证器即在任务性能与算力成本上持续超过现有无验证器基线。
- **评分理由**：直接回答子问题(1)，bandit 动态分配+无验证器，契合低成本大规模并行诉求。

## 三、基于验证器 / 重试 / 自适应采样的并行

#### 15. Verified Multi-Agent Orchestration: A Plan-Execute-Verify-Replan Framework (VMAO) [A]
- **总结**：把复杂查询分解为 DAG 子问题、经领域 Agent 并行执行、用 LLM 评估验证结果完整性并自适应重规划补缺。核心贡献是依赖感知 DAG 并行、以 LLM 验证器作为编排级信号的验证驱动重规划，以及平衡质量与资源开销的可配置停止条件。在 25 条专家市场调研查询上，回答完整性 3.1→4.2、来源质量 2.6→4.1。
- **评分理由**：直接回答子问题(1)（验证器驱动自适应重规划+停止条件控算力），面向多 Agent 编排，方法可落地。

#### 16. BEACON: Bayesian Optimal Stopping for Efficient LLM Sampling [A]
- **总结**：基于带贝叶斯学习的序贯搜索：顺序生成响应、实时更新奖励分布后验（免训练），当继续采样的边际收益不足以覆盖成本时停止，从而确定最优 N。实证显示平均采样量最高减少 80% 且保持响应质量，并可低成本生成偏好数据。
- **评分理由**：直接回答子问题(1)，贝叶斯最优停止给出确定最优 N 的原则性方法，80% 采样减少收益显著。

#### 17. Adaptive Inference-Time Compute: LLMs Can Predict if They Can Do Better, Even Mid-Generation [A]
- **总结**：生成式自评估方案，用生成式奖励模型让 LLM 在生成中途预测"重启是否更好"，据此决定多采样、早停剪枝或挑最优样本，无需外部奖励模型。Llama 3.1 8B 在 AlpacaEval 对 GPT-4 胜率由 21%→34%、GSM8K 84%→91%；仅用平均 1.2 个样本即可达到 16 样本改进的 74%，且 50–75% 样本可在早期剪枝。
- **评分理由**：直接回答子问题(1)，生成式自验证决定多采样/剪枝，收益（用 1.2 样本实现约 74% 增益）非常显著。

#### 18. Generative Verifiers: Reward Modeling as Next-Token Prediction (GenRM) [B]
- **总结**：用通用下一 token 预测目标联合训练"验证+生成"的生成式验证器，替代判别式分类器，天然支持指令微调、链式推理与测试时多数投票。在 Best-of-N 中相对判别式/DPO 验证器带来大幅增益：算法任务 5%→45.3%、GSM8K 73%→93.4%。
- **评分理由**：为子问题(1)提供更优验证器组件（提升候选选择质量），非直接回答 N 值决策，属可复用底层能力。

#### 19. Enhancing Large Language Model Reasoning with Reward Models: An Analytical Survey [B]
- **总结**：系统介绍奖励模型在 LLM 推理中的应用，覆盖架构、训练方法、评估与三大应用（推理时生成/选择、数据合成、RL 微调信号），并讨论开放问题。是验证器选择与动态 N 设计的重要背景综述。
- **评分理由**：作为验证器/RM 全景综述支持子问题(1)(2)的设计决策，但本身无落地方法与收益。

## 四、成本高效的多Agent编排 / Token 预算优化

#### 20. BAMAS: Structuring Budget-Aware Multi-Agent Systems [A]
- **总结**：先用整数线性规划在"性能-成本"间选择最优 LLM 集合，再用强化学习选择协作拓扑，最后按所选 Agent 与拓扑实例化执行。在三个任务上对标最新方法，取得相当性能的同时成本最高降低 86%。
- **评分理由**：直接回答子问题(2)（按预算选模型档位）并兼顾成本，86% 成本下降收益突出，方法可落地。

#### 21. Controlling Performance and Budget of a Centralized Multi-agent LLM System with RL (CoRL) [A]
- **总结**：集中式控制器 LLM 以"最大化性能+最小化总推理成本"的双目标强化学习，选择性协调一组专家模型，并支持推理期不同预算条件下的自适应行为。高预算模式超越最优专家 LLM，低预算经济模式仍保持较强性能。
- **评分理由**：直接回答子问题(2)（集中式控制器按预算路由模型档位），方法可落地、成本可控。

#### 22. Scaling Test-time Compute for LLM Agents [A]
- **总结**：首个系统研究测试时扩展应用于语言 Agent 的工作，探索并行采样、顺序修订、验证器与结果合并、多样性 rollout 及算力取舍。关键发现：扩展 TTC 可提升 Agent 性能；"何时反思"很重要；验证与合并中 list-wise 效果最好；多样化 rollout 有正向作用。
- **评分理由**：直接回答"多 Agent 大 N 时算力如何投最值"，为子问题(1)在 Agent 场景的取舍提供实证路线图。

## 五、Agent 扩展律（Scaling Laws）与动态Agent扩展

#### 23. Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters [A]
- **总结**：奠基性工作，研究基于验证模型的搜索与按 prompt 自适应更新响应分布两种测试时扩展机制。发现不同难度 prompt 下扩展效果差异巨大，提出 per-prompt compute-optimal 策略，比 best-of-N 效率提升 4 倍以上；较小基座模型在部分问题上可用测试时算力胜过 14 倍大的模型。
- **评分理由**：提供子问题(1)的理论与实践基础，4 倍效率提升、小模型可胜 14x 大模型，收益突出。

#### 24. Inference Scaling Laws: An Empirical Analysis of Compute-Optimal Inference [A]
- **总结**：实证研究"模型规模 vs 额外生成 token"在 greedy、多数投票、best-of-n、加权投票、两种树搜索下的成本-性能权衡。发现用推理策略扩展比扩展模型参数更计算高效；小模型+先进推理算法提供 Pareto 最优折中（如 Llemma-7B 配树搜索在 MATH 上超过 Llemma-34B）。
- **评分理由**：直接回答子问题(2)（小模型+更多采样替代大模型）与算力分配，指导档位与 N 的联合优化。

#### 25. Scaling LLM Inference with Optimized Sample Compute Allocation (OSCA) [A]
- **总结**：把"采样配置与样本数选择"形式化为学习问题，学习不同推理配置（模型、温度、语言等）的最优混合分配，在有限算力下最大化精度。代码生成上以 128 倍更少算力达到优于最佳单配置的精度，4 个推理任务上 25 倍更少算力；SWE-Bench agentic 工作流中较默认配置以 3 倍更少算力取得更好精度。
- **评分理由**：直接回答子问题(1)(2)（跨配置混合分配样本/算力），量化收益（25–128 倍省算力）极强。

#### 26. Towards a Science of Scaling Agent Systems [A]
- **总结**：跨 260 种配置、6 个 agentic 基准、5 种架构与 3 个 LLM 家族做受控评估，识别能力饱和效应：单 Agent 达到一定性能后协调收益递减、工具重度任务存在多 Agent 开销、无集中验证的架构更易传播错误。相对单 Agent 性能变化从 +80.8% 到 -70.0%，为 87% 留出配置选出最优架构，揭示"多 Agent 并非总是更好"。
- **评分理由**：直接回答大规模 N 时多 Agent 的代价-收益（扩展律），指导何时该用/不该用大 N，收益与结论清晰。

#### 27. AgentSpawn: Adaptive Multi-Agent Collaboration Through Dynamic Spawning [A]
- **总结**：通过运行时复杂度指标触发自适应 spawn 策略动态增加子 Agent，具备自动记忆迁移、技能继承、任务恢复与并发一致性协议。在 SWE-bench 等长程代码生成基准上较静态基线完成率提升 34%，并通过选择性切片将内存开销降低 42%。
- **评分理由**：直接回答子问题(1)（运行时复杂度触发动态 spawn），34% 完成率提升+42% 内存节省，收益明确。

#### 28. MonoScale: Scaling Multi-Agent System with Monotonic Improvement [B]
- **总结**：针对盲目扩 Agent 池会使路由在冷启动新增、异构、不可靠 Agent 时崩溃的问题，提出扩展感知更新框架：从成功与失败交互提取证据，蒸馏为可审计的自然语言记忆指导路由；将顺序增广形式化为上下文 bandit 并做 trust-region 更新，保证单调非降性能。重在"扩容而不崩"。
- **评分理由**：与子问题(1)(2)相关（动态增删 Agent/路由），但关注性能稳定非 token 成本，需改造用于 TCO。

#### 29. Understanding Agent Scaling in LLM-Based Multi-Agent Systems via Diversity [A]
- **总结**：用信息论框架证明 MAS 性能受"内在任务不确定度"而非 Agent 数量限制；同质 Agent 因输出强相关很快饱和，异质 Agent 提供互补证据扩展更强。提出 K* 量化有效通道数。实证 2 个多样 Agent 可匹敌或超过 16 个同质 Agent。
- **评分理由**：直接回答大规模 N 的性价比（异质小 N 可胜同质大 N），为子问题(1)(2)提供省钱的设计依据。

#### 30. Scaling Behavior of Single LLM-Driven Multi-Agent Systems [B]

- **评分理由**：直接回答多 Agent 系统成本/延迟优化与自适应路由，量化收益（成本 -80%、延迟 -70%）显著。
