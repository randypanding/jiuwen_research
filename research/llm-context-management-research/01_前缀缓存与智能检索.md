## 一、KV Cache / Prefix Caching 系统（核心）

### 论文

1. **SGLang: Efficient Execution of Structured Language Model Programs** 【✔ 重大】
   - 作者：Lianmin Zheng, Ying Sheng 等（UC Berkeley / Stanford）
   - 会议/年份：arXiv:2312.07104, 2023
   - 出处：https://arxiv.org/pdf/2312.07104v2
   - 相关性：提出 **RadixAttention**，用 radix 树管理并复用跨请求的共享前缀 KV cache，带 LRU 淘汰与 cache-aware 调度，是前缀缓存的核心系统论文，也是本方向理论基石。

2. **CacheBlend: Fast Large Language Model Serving for RAG with Cached Knowledge Fusion** 【✔ 重大】
   - 作者：Jiayi Yao 等
   - 会议/年份：arXiv:2405.16444, 2024
   - 出处：https://arxiv.org/pdf/2405.16444v3
   - 相关性：针对 RAG 场景中非前缀片段，通过"选择性 KV 重算"融合多个预计算 KV 缓存，突破"仅共享前缀可复用"的限制。

3. **Prompt Cache: Modular Attention Reuse for Low-Latency Inference** 【✔ 重大】
   - 作者：In Gim 等（Meta）
   - 会议/年份：arXiv:2311.04934, 2023
   - 出处：https://arxiv.org/pdf/2311.04934v1
   - 相关性：将频繁复用的 prompt 片段（prompt module）预计算并缓存其 KV 状态，模块化复用，降低首 token 延迟，是"模块化上下文复用"的早期代表。

4. **Mooncake: A KVCache-centric Disaggregated Architecture for LLM Serving** 【✔ 重大】
   - 作者：Ruoyu Qin 等（Moonshot AI）
   - 会议/年份：arXiv:2407.00079, 2024；后收录 USENIX FAST'25
   - 出处：https://arxiv.org/pdf/2407.00079v3
   - 相关性：以 KVCache 为中心的分离式架构，聚合 CPU/DRAM/SSD 构建分布式缓存，实现近 GPU 的全局前缀缓存，工业级前缀缓存的代表性架构。

5. **HotPrefix: Hotness-Aware KV Cache Scheduling for Efficient Prefix Sharing** 【✔ 重大】
   - 作者：顾荣等（南京大学）
   - 会议/年份：**SIGMOD 2025**（已修正）
   - 出处：https://wzbxpy.github.io/paper/SIGMOD26-Yuhang-HotPrefix.pdf
   - 相关性：针对 vLLM/SGLang 前缀共享局限，提出热度感知的多因素调度，按热度在 GPU/CPU 间换入换出共享前缀节点。

6. **Epic: Efficient Position-Independent Context Caching for Serving LLMs** 【✔ 重大】
   - 会议/年份：arXiv:2410.15332, 2024
   - 出处：https://arxiv.org/pdf/2410.15332.pdf
   - 相关性：实现位置无关（PIC）的上下文缓存，突破前缀缓存对"共享前缀"的硬性要求，对"按需拼装上下文"场景尤为关键。

7. **KVShare: Semantic-Aware Key-Value Cache Sharing** 【✔ 重大】
   - 会议/年份：arXiv:2503.16525, 2025
   - 出处：https://arxiv.org/pdf/2503.16525v1
   - 相关性：语义感知（semantic-aware）的多用户 KV 缓存共享，用 hash 识别可复用 token 片段，提升共享缓存命中率。

8. **KVCache in the Wild: Characterizing and Optimizing KVCache at a Large Cloud Provider** 【✔ 近3个月相关】
   - 会议/年份：arXiv:2506.02634, 2025
   - 出处：https://arxiv.org/pdf/2506.02634v1.pdf
   - 相关性：大规模云厂商真实负载上刻画前缀缓存命中特征并优化，涉及 GPU/主机内存/SSD 多级缓存，为"高频变动下缓存命中率"提供实证参考。

9. **CacheSolidarity: Preventing Prefix Caching Side Channels** 【✔ 近3个月相关】
   - 会议/年份：arXiv:2603.10726, 2026
   - 出处：https://arxiv.org/pdf/2603.10726v1
   - 相关性：研究前缀缓存命中/未命中导致的 TTFT 侧信道泄露（安全议题），多租户缓存安全性的补充视角。

### 开源项目

10. **vLLM（Automatic Prefix Caching）** 【✔ 重大】
    - GitHub：https://github.com/vllm-project/vllm ；文档：https://docs.vllm.ai/en/latest/design/prefix_caching/
    - 相关性：主流推理引擎，自 v0.4.0 起支持自动前缀缓存（APC），按块缓存并复用共享前缀 KV，是落地前缀缓存的事实标准之一。

12. **Mooncake** 【✔ 重大】
    - GitHub：https://github.com/mooncake-labs/mooncake
    - 相关性：Mooncake 论文开源实现（KVCache 分离式架构 / 前缀缓存）。

13. **GPTCache** 【✔ 重大】
    - GitHub：https://github.com/zilliztech/GPTCache
    - 相关性：语义缓存库，通过 embedding + 向量相似度检索语义相近查询并复用回答，语义缓存（非前缀）方向的代表。

14. **DeepSeek 上下文硬盘缓存（Context Caching）** 【背景参考】
    - 出处：https://api-docs.deepseek.com/zh-cn/news/news0802/
    - 相关性：工业级前缀缓存定价与失效实践参考（命中部分按 0.1 元/百万 tokens 收费），非论文/代码，仅作工程背景。

## 三、动态代码库 / 增量索引 / 缓存失效（本方向最贴合"高频变动"）

### 论文（近 3 个月新增，高度相关）

36. **CORVUS: Context Optimization and Reduction Via Underlying Synchronization for LLM Coding Agents** 【✔ 近3个月 · 高优先级】
    - 会议/年份：arXiv:2607.22711, 2026
    - 出处：https://arxiv.org/pdf/2607.22711
    - 相关性：**直接针对"高频变动代码库"**。指出文件被 agent 编辑或并发人改后，轨道快照过期导致重复读文件、上下文膨胀。CORVUS 解耦文件读取与其观察，维护同步的"相关文件注册表"，每次推理循环只注入当前内容，产出更轻量且与真实代码同步的轨迹。与"高动态代码库上下文管理"主题高度契合。

37. **Cat: Context as a Tool — Context Management for Long-Horizon SWE-Agents** 【✔ 近3个月 · 高优先级】
    - 会议/年份：arXiv:2512.22087, 2025
    - 出处：https://arxiv.org/html/2512.22087v1
    - 相关性：把上下文维护当作一等的"工具化"能力，主动、结构化地浓缩交互历史，克服 append-only 上下文与被动压缩的局限，在 SWE-Bench 上验证。与"动态按需检索/智能压缩"主题高度契合。

38. **CoMEM: Context Management with A Decoupled Long-Context Model** 【✔ 近3个月 · 高优先级】
    - 会议/年份：arXiv:2605.30842, 2026
    - 出处：https://arxiv.org/pdf/2605.30842 ；代码：https://github.com/horizon-llm/CoMem
    - 相关性：将内存（context）管理与主 agent 工作流解耦并并行执行，用 k-step-off 异步流水线掩盖上下文处理的延迟，奖励驱动的训练使内存模型捕获决策所需统计量。对应"长上下文模型利用 + 上下文管理并行化"。

39. **Context Rot: Progressive Prompt Ephemerality** 【✔ 近3个月 · 高优先级】
    - 出处：https://empromptu.ai/resources/context-rot-progressive-prompt-ephemerality ；相关白盒研究：https://arxiv.org/pdf/2607.17937v2
    - 相关性：诊断"上下文腐败"（Context Rot）——随时间累积的无关内容挤占上下文导致输出质量下降，提出分层上下文架构（Progressive Prompt Ephemerality）。这是"上下文管理提升生成质量"的核心动机证据。
