# Agent Swarm 学习机制：论文与开源项目精读总结与评分

> 精读时间：2026-08-15
> 原始问题：如何设计一种机制，使 Agent Swarm 能从执行实例（代码）中学习，并将学习成果沉淀到 **Spec** 和 **团队记忆** 中，同时避免"坏经验"的污染？其中三点硬性要求：
> 1. 经验提取与形式化：从成功/失败实例自动提取模式、最佳实践或反模式，转化为 Spec 条款（L2）或实现约定（L3）；
> 2. 记忆写入的判别与准入：实现"记忆写入须由判别侧裁定"，Spec Moderator 决定哪些实现细节值得写入 TEAM_MEMORY；
> 3. 防止经验污染：防止临时 Builder 的偶然选择（糟糕命名/设计）污染长期记忆与先验分布。

## 评分标准

- **A 档**：采用价值高，直接或近乎直接回答原始问题，核心机制可直接借鉴。
- **B 档**：采用价值中，部分回答原始问题，需改写或部分借鉴。
- **C 档**：采用价值低，仅间接相关，作背景或反例。

共精读与评分 **68 项**（方向一 26、方向二 24、方向三 18）。全部条目均经子代理逐篇 WebFetch 精读，总结与评分基于抓取到的真实内容。

# 详细精读总结

## 方向一：经验提取与形式化

### A 组（近期，≥2026-05-15）

#### Self-Harness（评分：A）
迭代三阶段：Weakness Mining（从执行轨迹挖掘模型特定失败模式）、Harness Proposal（生成多样且最小化的 harness 修改）、Proposal Validation（仅当通过回归测试才接受候选）。在 Terminal-Bench-2.0、SWE-bench Verified、AppWorld 上 9 个模型-基准组合全部提升，最高相对增益 132%。
**评分理由**：从失败轨迹提炼规则并带回归测试准入门控，近乎直接回答原始问题，可借鉴为团队记忆的"验证后沉淀"机制。

#### AutoSpec（评分：A）
用反例引导归纳综合（CEGIS）+ 归纳逻辑编程（ILP）自动演化安全规则：评估规则、挖掘误报/漏报反例、ILP 学习区分谓词、选择最优修订直至收敛。规则 F1 达 0.98/0.93，误报降低最多 94%，规则可读、可审计、可泛化。
**评分理由**：直接回答"从执行轨迹提炼规则进 Spec 并防污染"，自带反例驱动、可审计、防误报机制，核心机制可直接借鉴。

#### JERP（评分：A）
从同一批交互轨迹同时更新长期"经验规则池"与策略，决策时检索相关规则注入上下文；每轮用轨迹优化策略，并对比当前 rollout 与参考成功轨迹来修订规则池。在 AlfWorld、WebShop 上一致提升。
**评分理由**：直接从执行轨迹联合学习并沉淀经验规则池，含与成功参照对比的纠偏机制，核心机制可借鉴。

#### MemToolAgent（评分：A）
用 reflection 基于环境与用户反馈把错误执行蒸馏成 critique 存入结构化记忆条目，检索时按记忆相似度分布动态选择条目数量。在 WorkBench、NESTFUL、PEToolBench 上分别提升 29%、80%、17%。
**评分理由**：统一记忆格式 + 从执行反馈蒸馏错误 critique + 动态检索，核心机制可直接借鉴。

#### Spec-Agent（评分：A）
Agentic 系统在大型 C++ 代码库上合成可验证形式化规格：用静态分析与运行时堆追踪为每函数选目标语言，泛化功能测试为 fuzz harness，经反例引导迭代精炼候选规格。为 85% 目标函数合成有效规格，零假阳性，token 成本低 10 倍。
**评分理由**：从代码执行痕迹提炼并验证形式化规格、零假阳性，直接对应"沉淀到 Spec + 防坏规格污染"。

#### SkillAdaptor（评分：A）
免训练的 step 级技能自适应，带显式失败归因：定位首个故障步骤、把责任关联到候选技能、在显式接受检查下针对性更新并冻结 backbone。在 WebShop、PinchBench、Claw-Eval 上优于基线。
**评分理由**：从失败轨迹做 step 级归因并带显式接受检查更新技能库，防污染机制精确，可借鉴到团队技能库。

#### SKILL-KD（评分：A）
对比式技能蒸馏：把学生失败与教师轨迹差异蒸馏为可执行技能补丁，重跑验证失败则迭代精炼；用 Drift-Aware Skill Consolidation 决定补丁是新增/删除/修改规则还是跳过，防止技能漂移。
**评分理由**：从执行实例蒸馏技能并用重跑验证与 drift-aware 合并防污染/漂移，与原始问题吻合度最高之一。

### B 组（奠基 / 重大）

#### Reflexion（论文，评分：A）
奠基框架：不更新权重，agent 对任务反馈做言语反思，把反思文本存入 episodic memory buffer 引导后续决策。HumanEval pass@1 达 91%。
**评分理由**："从执行反馈反思并沉淀记忆"的鼻祖，直接回答学习沉淀环节，虽缺防污染门控但为后续提供基础。

#### Self-Refine（评分：B）
单一 LLM 同时作生成器、反馈提供者与精炼器，对初始输出迭代自我反馈精炼。7 个任务相对提升约 20%。
**评分理由**：通用"生成-反馈-精炼"循环可借鉴为 Spec 自校验，但非专门针对执行实例沉淀，需改写。

#### Self-Debugging（评分：B)
用 few-shot 教 LLM 借助执行结果与代码解释"橡皮鸭调试"，无需人工反馈即可修复预测程序。Spider 上（无单测）提升 2-3%、最难级别 9%，有单测最多 12%。
**评分理由**：从执行反馈自 debug 识别错误，可作防污染前置甄别器，但不直接形成沉淀规则。

#### Voyager（论文，评分：A）
Minecraft 具身终身学习 agent：自动课程 + 不断增长的"可执行代码技能库" + 迭代提示（融入环境反馈、执行错误、自我验证）。比 SOTA 多获取 3.3 倍独特物品，技能库可泛化到新世界。
**评分理由**：奠基性"从执行经验沉淀可执行技能库 + 自我验证改进"，直接对应团队技能沉淀与质量把关。

#### RLEF（评分：C）
用执行反馈作为奖励信号，端到端 RL 训练代码合成模型在推理期多步利用自动反馈。8B/70B 达到新 SOTA，采样量降一个数量级。
**评分理由**：把执行反馈**内化进模型权重**，而非外部 Spec/记忆沉淀，与"外置沉淀 + 防污染"方向不符，仅背景参考。

#### SpecGen（评分：A）
两阶段生成程序形式化规格：对话式引导生成，失败时对规格施加四种变异算子并用启发式选出可验证规格。385 程序中 279 个生成可验证规格。
**评分理由**：从程序生成形式化规格并用变异+验证筛选合格者，直接对应"沉淀到 Spec、防坏规格进入"，奠基范本。

#### AutoReSpec（评分：B)
协作式 LLM 规格生成：动态按程序结构选 LLM 对与提示配置，主 LLM 输出无效时用验证器反馈精炼。72 个 Java 程序中通过 67 个。
**评分理由**：提供"验证器反馈→协作修复"的纠错环，但面向单程序生成，未覆盖 swarm 团队记忆沉淀。

### C 组（背景）

#### VeriSpecGen（评分：A）
"可追溯细化"框架在 Lean 中合成意图对齐规格：拆解原子需求、生成带 traceability map 的需求定向测试验证，失败时归因到具体需求做子句级修复。VERINA SpecGen 86.6%。
**评分理由**：验证后采纳 + 可追溯归因，可直接借鉴到团队 Spec 沉淀与质量把关。

#### AutoRefine（评分：A）
从执行历史提取并维护"双形态经验模式"：过程性子任务封装为专用 subagent，静态知识提炼为 skill pattern；对模式打分、剪枝、合并防止仓库退化。
**评分理由**：双形态经验 + 维护剪枝机制可直接作为团队记忆组织与防腐设计模板。

#### RIMRULE（评分：A)
LLM 从 failure traces 提出紧凑可解释规则，用最小描述长度（MDL）目标合并提炼，规则同时以自然语言与符号形式存储、可跨模型复用。
**评分理由**：MDL 引导规则学习兼顾提取与防污染且可迁移，机制可直接借鉴。

#### ERL（评分：B）
对任务轨迹与结果反思生成跨任务可迁移 heuristics，测试时选择性检索并注入上下文。消融显示选择性检索至关重要。
**评分理由**：经验提炼与检索机制可借鉴，但缺显式门控/验证防坏经验进入，需改写补充质量门槛。

#### AgentErrorTaxonomy（评分：B）
模块化错误分类（memory/reflection/planning/action/system）+ 标注数据集 + AgentDebug 调试框架。
**评分理由**：错误分类与根因定位可为"哪类经验值得沉淀"提供分诊基础，但不是直接的学习-沉淀-防污染闭环。

#### AgentRR（评分：A）
把 record-and-replay 引入 agent：记录交互与内部决策轨迹，归纳为结构化"经验"（工作流+约束），后续相似任务重放；核心是"多层级经验抽象"与 check function（信任锚）保证回放安全。
**评分理由**：record→抽象→带 check 重放 的闭环几乎直接回答原始问题，信任锚机制可直接借鉴。

#### Daikon（评分：B, 经典）
动态不变量挖掘：在正确执行的测试输入上运行程序，推断程序点 likely invariants，经开发者 review 后泛化沉淀。
**评分理由**：作为经典范式启发"从执行提取规格 + 审查防污染"的思路，但非 agent 场景，需转化。

### D 组（开源项目）

#### harness-loop（评分：A）
约 500 行 Python 的自改进 harness：run→mine→gate→inject 循环，强模型从失败轨迹挖掘公共失败模式提出规则，回归门控验证（无已通过任务失败且至少一个失败任务通过）才固化进 system prompt。15 任务真实演进 87%→100%。
**评分理由**：本就是"学习+沉淀+防污染"的最小完整实现，门控规则可直接借鉴。

#### Reflexion（开源代码，评分：B）
官方代码库（所有anj 为 fork，orig 为 noahshinn/reflexion），实现语言强化学习，支持推理/决策/编程任务。
**评分理由**：自我反思奠基范式的基础思路，但记忆是逐任务 episodic、不跨任务沉淀为团队 Spec，且无验证门控，反是"坏经验可能污染"的反例参考。

#### Voyager（开源代码，评分：B）
Minecraft 持续学习 agent，技能库 + 自我验证三组件。代码库活跃度中等（最新提交 2023-07，35 commits）。
**评分理由**：技能库+自我验证机制可借鉴，但面向游戏域、验证只对单技能，对团队协同/全局坏经验治理不足。

#### BREW（评分：B)
把交互轨迹转化为可检索"recipes"知识库，每条记录 what to do / when it applies / what to watch out for；双模式 recall-first / generate-if-needed。成功率 71%→89%。
**评分理由**：recipe 提取与检索结构直接可用，但合成后直接入库、缺回归门控/冲突仲裁，需补防污染环节。

#### TraceCoder（评分：C）
trace-driven 多 agent 自动调试：代码插桩→错误分析→修复，跨多轮迭代。多个基准优于 Self-Debugging。
**评分理由**：从 trace 驱动调试与修复，但产出是修复后的代码而非可沉淀到 Spec/记忆的抽象经验，无防污染机制。

## 方向二：记忆写入准入与防经验污染

### A 组（近期，≥2026-05-15）

#### ConsistencyGate（评分：A）
写入时记忆准入门：对候选事实 m 用 LLM 自查询 K 次求"软支持分数"，超过阈值才准入；模型无关、无需微调。构建 LoCoMo-Contam、MSC-Contam 污染基准。
**评分理由**：写入准入门 + 判别侧支持分数的完整实现与基准，可直接借鉴为 swarm 沉淀经验前的判别裁定层。

#### Memory Poisoning Attacks in LLM Agents（评分：B)
系统研究记忆投毒：识别 4 条写入通道、9 类结构性漏洞、6 类攻击分类学，构建 MPBench 基准。激进"写入+检索"的 Agent 更易被利用。
**评分理由**：框定"坏经验如何通过写入通道进入"的威胁面，但只到威胁模型与基准层面，未给判别侧准入机制。

#### LazyMem（评分：C）
把记忆构建推迟到查询时，轻量模型对候选池选择性保留并压缩仅与查询相关的内容。LongMemEval 4B 模型准确率 0.85。
**评分理由**：解决写入时信息损失与检索噪声矛盾，非坏经验判别/准入，仅间接相关。

#### CuraWeb（评分：C）
预训练数据策展：质量/冗余/多样性联合优化，双轨清洗 + 混合去重 + 多目标采样。3B 规模平均提升 1.8%。
**评分理由**：属预训练语料质量策展，与 Agent 运行时记忆写入是两个层面，仅背景反例。

#### GovMem（评分：A）
将"何时拒绝写入"建模为写路径治理：依赖感知支持度估计、反证检索、作用域分配，输出 promote / reject / needs-review 三选一。合成压力测试 false promotion 从 0.597 降到 0.040；来自 coding-agent 执行 trace，识别"相关 trace 中的虚假提升"。
**评分理由**：直接命中"写入准入判别侧裁定 + 防止坏经验从执行实例污染团队记忆"，且针对代码 agent 执行 trace，核心可借鉴对象。

#### MIND（评分：B）
轻量记忆注入防御：用意图感知信息瓶颈（IB）从初始意图与逐轮行为提取紧凑"意图-行为"表征，轻量检测器识别恶意记忆。ASR 平均降 55%+。
**评分理由**：提供意图信号驱动判别特征，但作用于检索结果而非写入准入，需改写。

#### MemPoison（评分：B）
记忆投毒基准与分析（1227 用例、4 攻击、3 通道、3 基质）；三层分类学 L1 单条/L2 组合/L3 触发式休眠破坏。证明写时一致性检查无法可靠抑制 L2/L3。
**评分理由**：精确揭示写时准入机制（如 ConsistencyGate）的盲点，为"判别侧裁定"设计提供必须规避的结构性约束，属高价值约束。

### B 组（奠基 / 重大）

#### A-MAC（评分：A）
把记忆准入重构为结构化决策：将记忆价值分解为未来效用、事实置信度、语义新颖性、时间近度、内容类型先验五因子；轻量规则特征 + 单次 LLM 辅助评估。LoCoMo F1 0.583，延迟降 31%。
**评分理由**：可解释的结构化准入判别框架，事实置信度因子天然防坏经验、"内容类型先验"直接对应防污染先验分布，可作为判定层蓝本。

#### SSGM（评分：A）
治理架构：记忆演化与执行解耦，固化前强制一致性验证、时间衰减建模、动态访问控制三道关卡；给出记忆腐化风险分类学。
**评分理由**：明确"记忆固化前须经一致性/访问控制判别"的治理架构，直接对应"写入由判别侧裁定、防坏经验进入长期记忆"。

#### Memory Security Survey（评分：B）
Memory Lifecycle Framework：六阶段（Write/Store/Retrieve/Execute/Share/Forget）× 四安全目标；提出 Verifiable Memory Governance（VMG）五种架构原语，主张存储时锚定 provenance、版本化。
**评分理由**：提供写入阶段防护与治理原语的系统性框架，但为综述/蓝图而非落地机制，需改写。

#### MemoryBank（评分：C)
基于艾宾浩斯遗忘曲线选择性保持记忆，按时间与重要性强化/遗忘。
**评分理由**：选择性保留依据是时间/重要性而非"坏经验判别"，无写入准入与防污染，仅间接相关。

#### Generative Agents（评分：C)
记忆流 + 反射合成 + 动态检索，25 个 agent 涌现可信社会行为。
**评分理由**：奠基"经验→记忆→反思"范式，但记忆全部写入、无准入/判别/防污染，仅背景基石。

#### MemGPT（评分：C)
OS 式分层内存，数据在快/慢内存间移动，模型管理各内存层级。
**评分理由**：OS 式内存治理架构可参考，但核心是容量管理而非判别侧准入，仅间接相关。

#### A-MEM（论文，评分：C）
Zettelkasten 原则组织记忆：新增记忆生成结构化笔记、建立链接、触发已有记忆演化。
**评分理由**：关注记忆组织/索引/演化，写入端无准入判别，坏经验同样会被索引传播，仅间接相关。

#### fDPO（评分：B）
用训练好的 reward model 监控 DPO 偏好数据质量，丢弃低质量样本以获得更精确数据集。
**评分理由**："判别过滤坏数据以保护先验"的范式可类比迁移为记忆写入的判别裁定，但场景不同需改写。

#### Oasis（评分：C）
预训练语料策展与评估：规则过滤 + 负样本中心神经过滤 + 自适应去重。
**评分理由**：属预训练语料质量过滤平台，与 Agent 记忆写入准入层面不同，仅背景反例。

#### GFCR Survey（评分：C）
系统综述 LLM RL rollout 策略，提出 Generate/Filter/Control/Replay 生命周期分类。
**评分理由**：Filter/Replay 思想与判别沉淀技能相关，但对象是 RL 轨迹而非记忆写入准入，间接相关。

### C 组（背景）

#### Selective Memory: Write-Time Gating（评分：A）
写入时门控：用复合显著性分数（来源信誉、新颖性、可靠性）实时过滤进入记忆的知识对象，用版本链保留被替换的旧状态。8:1 干扰比下写门控保持 100% 而读时过滤（Self-RAG）崩塌至 0%，成本仅 1/9。
**评分理由**：直接给出写入准入的完整机制 + 版本链保护先验，量化证明"写时门控优于读时过滤"，可整体迁移到 swarm 记忆写入侧。

#### Memory Poisoning Attack and Defense（评分：A）
研究记忆投毒并在 EHR 场景实测；提出两类防御：输入/输出复合信任评分、记忆净化（信任感知检索 + 时间衰减 + 模式过滤），并指出信任阈值需精细校准。
**评分理由**：直接正面回答"防污染"，给出可落地的多层防御，记忆净化与信任感知检索可直接借鉴。

#### Human-Inspired Memory（评分：B)
生物启发六机制：睡眠期整合、干扰式遗忘、记忆痕迹成熟、再巩固、实体知识图谱、混合多线索检索。VSCode issue 数据集去重整合保留精度 97.2%。
**评分理由**：对"沉淀整合"贡献直接、对"防坏经验污染"仅间接（靠遗忘/整合疏解而非准入判别），需改写组合。

#### SimpleMem（评分：B)
语义无损压缩的终身记忆：语义结构化压缩 + 在线语义综合 + 意图感知检索。LoCoMo F1 提升 26.4%，token 降 30 倍。
**评分理由**：提供压缩/去冗余的沉淀手段，但缺写入准入与污染防护，须与准入机制组合。

### D 组（开源项目）

#### Letta / mem0（评分：B)
类 OS 分层记忆（核心/归档），agent 可自我编辑记忆块；sleep-time agents 从轨迹学习；基于 git 的 Context Repositories 支持多子代理并发写记忆再冲突合并。活跃（主仓库标记 legacy，开发迁往 letta-code）。注：用户提供的 `lettaverse/letta` 不存在，正确仓库为 `letta-ai/letta`。
**评分理由**：对"学习沉淀/团队记忆并发写"借鉴价值高，但缺写入准入与污染防护，须叠加判别/防污染层。

#### A-MEM（开源，评分：B）
Zettelkasten 动态记忆组织，ChromaDB 向量存储，多 LLM 后端。31 commits，最新 2025-12-13。
**评分理由**：提供记忆组织与演化借鉴，但缺准入/防污染机制，仅部分对题。

#### Memgar（评分：A）
记忆运行时防御：每次写入/检索/工具结果进入模型前经多层检测并事后检测篡改。含 801 条正则覆盖 OWASP ASI06、语义相似度、MINJA 注入检测、来源信任 + 时间衰减、行为基线、fail-closed；提供 MemoryWriteGateway（人机审批）、SecureMemoryStore、TrustAwareRetriever，集成 LangChain/LlamaIndex/CrewAI/MCP。v1.4.0（2026-06-12）。
**评分理由**：直接实现写入侧判别裁定与防污染（多层准入、信任衰减、fail-closed、审计回滚），带框架集成，可直接接入 swarm 记忆写入路径。

## 方向三：Swarm / Spec / 团队共享记忆 / 裁定

### A 组（近期，≥2026-05-15）

#### Governed Shared Memory / MemClaw（评分：A）
形式化"fleet-memory 问题"，共享记忆为受治理分布式状态 F=(A,M,G,P,T)；识别四大失败模式（未授权泄漏、陈旧传播、矛盾持续、来源崩塌）；定义作用域检索、时间取代（矛盾写入标记旧行为非活跃）、来源追踪、策略治理传播。生产级 MemClaw 实例化，来源追踪 100% 重建深度 4 推导链。
**评分理由**：提供可借鉴的共享记忆治理原语与失败模式清单（矛盾取代、作用域、来源追踪），正是防坏经验污染与团队记忆治理的直接答案。

#### Beyond Self-Talk（综述，评分：C）
以"通信"为中心的多代理综述，提出系统级/系统内通信分类框架。
**评分理由**：背景性综述，无针对经验沉淀/判别方裁定/团队记忆的具体机制，仅背景。

#### GateMem（评分：B)
多主方共享记忆治理基准：四域 91 个长程 episode、2218 隐藏 checkpoint，联合评测效用/访问控制/主动遗忘。结论：当前记忆代理远未达共享机构级可靠性。
**评分理由**：定义团队共享记忆治理评测维度，可检验防污染效果，但缺"从代码学习→Spec 沉淀"，需改写为评测层借用。

### B 组（奠基 / 重大）

#### AutoGen（评分：C）
多代理对话框架，代理可定制/可对话/可组合 LLM·人工·工具。
**评分理由**：可作 swarm 基础设施背景，但对"学习→Spec 沉淀→防污染"无直接贡献。

#### MetaGPT（评分：B)
把 SOP 编码进 prompt 流水线，角色分工，让领域专长代理验证中间结果、减少级联幻觉。
**评分理由**：SOP-as-Spec 与中间校验可部分借鉴，但 SOP 是静态预置、非从执行动态学习沉淀，也无团队共享记忆。

#### ChatDev（评分：B)
聊驱动软件开发，chat chain 指引"沟通什么"，communicative dehallucination 指引"如何沟通"（评审/自纠）。
**评分理由**：判别/评审式沟通与代码调试经验可启发"裁定写入"设计，但缺团队记忆与经验沉淀闭环。

#### Open Agent Specification（评分：B)
声明式语言 Agent Spec 统一定义代理与工作流，跨框架可移植，含标准化评测 harness。
**评分理由**：是"Spec 驱动"的表示与评测范式可借鉴对象，但缺"学习→沉淀→防污染"的动态机制。

#### INMS（评分：A)
异步共享"对话式记忆池"：交互产生 Prompt-Answer 对，专用 LLM scorer 按 rubric 评分过滤（阈值决定是否写入），检索器当可调优 moderator 缓解回声室。三个数据集显著提升。
**评分理由**：判别方评分门控写入 + 共享记忆池 + 动态检索中介正是防坏污染/团队共享记忆/经验沉淀的直接机制，稍作改造移至代码执行场景即可借鉴。

### C 组（背景）

#### Collaborative Memory（评分：A)
多用户多代理共享记忆框架：二部图编码不对称、时变访问控制，维护私有/共享双层记忆，每条携带不可变来源属性，支持事后审计；读/写策略强制约束。
**评分理由**：近乎直接回答"团队共享记忆 + 防止坏经验传播"的写入治理子问题，来源属性与写策略机制可原样借鉴。

#### RUMAD（评分：B)
把多代理辩论的通信拓扑控制建模为 RL，内容无关观察 + 多目标奖励 + PPO 动态调整边权 + 双阈值控制信息可见性。token 降 80%+ 且准确率提升。
**评分理由**：提供协调者裁定与信息可见性控制思路（可借鉴"内容无关的污染判定"），但缺"沉淀到记忆/Spec"与经验写入层面。

#### Majority-Following Coordination（评分：C, 反例）
从复杂系统研究 AI 代理组"跟随多数"行为：多数力随组规模衰减，存在临界规模，超过则无法共识；先进 LLM 可在 1000+ 规模协调。
**评分理由**：提供背景与反例——多数共识有规模上限且共识≠正确，多数跟随可能放大坏经验，警示"判别方裁定"不能依赖简单多数。

### D 组（开源项目 / 论文）

#### Multi-Agent Council Review（评分：B)
生产级 MCP 服务器：多 agent 并行 EXPLORE → 合成器去重 → 全体投票 1-10 分 → 按共识%与优先级排序输出，通过投票过滤噪声。含上下文自适应、熔断、密钥脱敏。
**评分理由**：共识裁定与噪声过滤机制可直接借鉴（判别方如何用共识裁定经验），但未实现"裁定结果写入 Spec/共享记忆"的沉淀闭环。

#### Conclave（评分：A)
编码代理方法论文艺插件：可组合 skills（TDD、写计划、验证、code review 等）；可选多代理共识（全员同意→高优先级、多数→中、单一→考虑），关键问题阻塞；message bus / 公告板实现并行任务共享发现并在 wave 间累积项目知识；796 次基准实验方法学带来 +10-12pp 质量提升。
**评分理由**：既有多代理共识裁定分级，又有公告板/文档实现"从执行沉淀知识"，且"方法学>模型"结论支持把经验沉淀到 Spec/技能，可较大程度直接借鉴。仅缺显式"防坏经验污染"治理层。

#### guilde-lite（评分：C)

**评分理由**：提供角色分层与评审代理的工程环境参考，但无共享记忆治理或经验写入机制，仅作背景/模板。

#### Awesome Agent Swarm（评分：C)
活跃维护的 swarm 领域资源清单（框架、协议、智能、治理、论文与基准分类）。

**评分理由**：直接回答原始问题——把"判别方/协调者裁定写入"形式化为选择体制，给出治理原则与分层架构，是防污染 + 共享记忆治理最贴近的思想来源。

# 综合洞察与建议

## A 档（优先借鉴）概览

三个方向中，A 档共 21 项，已覆盖原始问题的完整机制闭环：

**1. 经验提取与形式化（从执行实例→规则/规格/技能）**
AutoSpec、SpecGen、Spec-Agent（执行→形式化规格，含验证门控）；Self-Harness、SKILL-KD、SkillAdaptor（失败轨迹→技能/规则，带回归验证）；JERP、RIMRULE、AutoRefine、MemToolAgent、AgentRR、VeriSpecGen（轨迹→经验池/规则，含纠偏/维护/信任锚）；harness-loop（最小完整 run→mine→gate→inject 实现）。

**2. 记忆写入的判别与准入（判别侧裁定）**
A-MAC（五因子结构化准入）、SSGM（固化前三道关卡）、ConsistencyGate（写入期自一致性门控）、GovMem（promote/reject/needs-review 三态裁定）、Selective Memory（写时门控 + 版本链）、Memgar（多层 fail-closed 准入 + 审计回滚）。

**3. 防经验污染（坏经验不进长期记忆/先验）**
GovMem、Selective Memory、Memgar、ConsistencyGate（写入侧防污染）；SKILL-KD（drift-aware 合并防漂移）；MemPoison/MIND/Memory Security Survey（揭示写时防御盲点，作约束）。

**4. 团队共享记忆与裁定（判别方/协调者）**
Governed Shared Memory/MemClaw（治理原语 + 失败模式）、INMS（判别方评分门控 + 共享记忆池）、Collaborative Memory（来源属性 + 写策略）、Governed Collaborative Memory as Artificial Selection（选择体制 + 分层架构）、Conclave（共识裁定 + 公告板沉淀）。

## 关键设计洞察

- **写入时优先于读取时**：Selective Memory 与 ConsistencyGate 均以量化实验证明"写时准入优于读时过滤"，支撑原始问题"记忆写入须由判别侧裁定"的设计方向。
- **判别不能只靠单点写完检查**：MemPoison 证明单条写时一致性检查无法抑制组合（L2）与触发式（L3）污染，需叠加来源追踪、作用域、时间取代等治理原语（MemClaw）与事后审计（Memgar）。
- **防污染需"验证 + 维护"双保险**：Self-Harness/RegSpec 靠回归/验证门控阻止坏条目入 Spec；AutoRefine/SKILL-KD 靠打分/剪枝/合并与 drift-aware 处理在沉淀后继续纠偏，防止经验库随时间退化。
- **多数共识不等于正确**：Majority-Following 反例提醒，判别方裁定不能依赖简单多数，需引入可信来源、作用域与内容无关的污染判定（RUMAD）。
- **Spec 表示需与动态学习打通**：Open Agent Spec 提供静态表示与评测，INMS/AgentRR 提供动态沉淀与准入，二者应组合成"学习→判别→写入 Spec/记忆"的完整管线。

## 完整方案拼装建议

综合 A 档，一个符合原始问题的机制骨架可由以下拼装：
**从执行实例学习**（SkillAdaptor/SKILL-KD 做失败归因与技能蒸馏）→ **形式化为规则/规格**（AutoSpec/SpecGen/Spec-Agent，含验证门控）→ **判别侧裁定准入**（A-MAC/GovMem/ConsistencyGate/Selective Memory 做写入门控，Memgar 做 fail-closed 多层防御）→ **沉淀到团队记忆**（MemClaw 的治理原语 + Governed Collaborative Memory 的分层架构 + INMS/Conclave 的判别方/共识裁定）→ **沉淀后持续维护防污染**（AutoRefine/SKILL-KD 的剪枝合并与 drift-aware 处理）。
