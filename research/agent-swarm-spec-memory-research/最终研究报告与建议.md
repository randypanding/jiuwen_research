# Agent Swarm 学习机制研究报告：执行经验沉淀到 Spec 与团队记忆及防污染设计

> 报告日期：2026-08-15
> 本报告由三个并行研究子代理分方向研读后汇总形成，覆盖 68 篇论文与开源项目的精读、评分与机制建议。

---

## 一、研究问题（原始问题）

**总问题**：如何设计一种机制，使得 Agent Swarm 能够从执行实例（代码）中学习，并将学习成果沉淀到 Spec 和团队记忆中，同时避免"坏经验"的污染？

三个子问题：

1. **经验提取与形式化**：如何从成功的或失败的实例中自动提取模式、最佳实践或反模式，并将其转化为 Spec 条款（L2）或实现约定（L3）？
2. **记忆写入的判别与准入**：如何实现范式中的"记忆写入须由判别侧裁定"？Spec Moderator 如何决定哪些实现细节值得写入 TEAM_MEMORY？
3. **防止经验污染的机制**：如何防止临时 Builder 的偶然选择（如糟糕的命名或设计）污染长期记忆和先验分布？

## 四、建议一：经验提取与形式化（子问题一）

### 4.1 核心挑战与设计空间

三个核心挑战：**(a) 信用分配**——失败轨迹中多数步骤是正确的，以整条轨迹为单位反思会把失败信号扩散到无关步骤，产生过宽或错误的修订；必须做 step 级归因（SkillAdaptor 的核心动机）。**(b) 泛化与过拟合的张力**——从少数实例提炼的条款容易只修复观测到的失败（坏经验/偶然选择由此入库），需要回归与留出集双重检验。**(c) 形式化粒度**——经验应以自然语言启发式、谓词化规则还是可验证规范条款存在，决定了可审计性与可验证性。

设计空间四维：提取单位（轨迹/聚类/对比轨迹对）、归因方式（结果级/首错步骤级）、形式化表示（NL 经验条款 → 符号规则 → 谓词化 Spec 条款，对应 L3→L2 的硬度梯度）、验证手段（同例重跑/回归门控/留出集泛化/MDL 剪枝）。

### 4.2 分步管线与可直接采用的决策规则

**① 提取**：对带可验证结果的执行轨迹做失败聚类而非逐条反思，让模型推理"重复出现的失败模式"而非孤立错误（Self-Harness Weakness Mining）；有条件时构造对比轨迹对 (失败 τ⁻, 参照成功 τ\*)，用对比蒸馏定位根因（RIMRULE 的 EBL、SKILL-KD 的师生差异蒸馏）。

**② 归因**：定位"首个可行动故障步骤"（first actionable fault step），把责任关联到具体技能/条款，只修订被归因对象、不动无关条目（SkillAdaptor 的 Attribution→Modification→Qualification 三段）；给每条候选规则打错误类型标签（dec/sel/arg），或接入 AgentErrorTaxonomy 分诊。**归因权重规则**：某条款/技能被 ≥2 条独立失败轨迹的首错步骤命中才立项修订；单实例命中的只进"观察区"，不进入形式化。

**③ 形式化**：按 Explanation-Based Learning 生成有据解释后剥离实例特定细节再泛化；每条条款强制双形态存储——自然语言（给人读、给检索）+ 固定字段/闭合词表的符号形式（给 MDL 计算与结构化匹配，RIMRULE 的 Domain/Qualifier/Action/Strength/ToolCategory 五字段模式可直接套用）。**L2/L3 路由规则**：能表达为谓词组合并可机器判定的（不变量、安全边界、接口契约）→ L2 Spec 谓词条款（AutoSpec 谓词库模式、SpecGen/Spec-Agent 的可验证规范）；属执行习惯、流程次序、工具用法 → L3 实现约定/harness 规则（Self-Harness、harness-loop）。

**④ 验证（防坏经验的核心）**：三层递进——
- **预检**：候选条款注入后必须能在其来源失败实例上修复该失败，且通过语言形式检查（if–then 形式、长度上限），否则退回重提（RIMRULE）；
- **回归门控（接受条件）**：仅当"零已通过任务回归失败 ∧ 至少 1 个原失败任务转为通过"才接受（harness-loop 门控规则，与 Self-Harness 的"无退化才晋升"一致）；多个候选同时通过则合并进下一版 Spec，被拒候选留档不生效；
- **泛化检查**：留出任务集（其轨迹从未用于提取）上指标不降方可固化，防止对观测失败过拟合（Self-Harness held-out 验证）。

**⑤ 沉淀与维护**：入库条款携带溯源（来源轨迹、归因证据、验证结果）与版本号；库维护用 **MDL 剪枝**：目标 MDL(H)=L(H)+L(D|H)，仅当"删除/泛化一条规则所节省的模型码长 > 其导致的失败修复数下降对应的数据码长增加"时才接受编辑，贪心迭代至无改进（RIMRULE）；对已入库条款周期性用新反例做 CEGIS 式修订——挖掘误报与漏报反例，用 ILP 找出区分性谓词再生成候选修订，按 F1 优先、精度次之、规则更短加分的打分选优（AutoSpec，4–5 轮收敛、规则 F1 达 0.98/0.93）。

### 4.4 局限性与开放问题

- 回归门控依赖回归集质量：任务集小或覆盖偏时，"零回归"≠真泛化。
- 归因仍有噪声：首错步骤定位靠 LLM 判断，错误归因会修订无辜条款；需多轨迹命中阈值缓解但会拖慢沉淀速度。
- MDL/ILP 需结构化标注：真实 swarm 中 safe/unsafe 监督稀缺，需转向奖励信号替代。
- 组合与休眠污染：写时验证无法防范"各自无害、组合有害"及延迟生效的坏条款，需与治理原语（来源追踪、时间取代、事后审计）配合。
- 成功经验的提取弱于失败：多数方法以失败驱动，从成功实例提炼最佳实践仍需对比蒸馏。

### 4.5 关键结论

1. **提取要聚类、归因要到步**：以聚类后的重复失败模式和首错步骤为提取/归因单位，是从源头防坏经验的第一道闸。
2. **接受规则必须双重：修复+零回归**："≥1 修复 ∧ 0 回归 ∧ 留出集不降"三条同时满足才晋升 Spec，是防过拟合污染的最小充分门控。
3. **条款须双形态+可审计**：自然语言保证可读与检索，固定词表符号形式支撑 MDL 剪枝与结构化冲突检测。
4. **沉淀不是终点**：入库后持续做 MDL 剪枝与反例驱动（CEGIS/ILP）的条款演化，否则规则库会随时间退化为误报源。
5. **L2/L3 分流按"可否谓词化验证"决定**：可验证的进 L2 受机器判定，执行性的进 L3 受回归门控，两者共用同一提取—归因前端。

## 五、建议二：判别侧准入与防经验污染（子问题二、三）

### 5.1 核心挑战

**(1) 写时 vs 读时。** 污染一旦写入即成为后续所有检索的假前提——即使 oracle 检索器也会把脏记忆召回并放大，形成"污染级联"。量化证据明确：8:1 干扰比下，读时过滤（Self-RAG 式）准确率塌至 0%，而写时门控保持 100%，且查询成本仅为 1/9（Selective Memory）。**结论：准入必须放在写时，读时过滤只能作补充。**

**(2) 相关性≠证据，重复≠独立。** GovMem 指出多 agent 重复同一 claim 可能源自共享 prompt、共享工具、复制传播或过期作用域，朴素计票会把相关回声当成独立支持。Swarm 场景下，临时 Builder 的一个偶然命名被后续 trace 引用、复制，就会表现为"高支持度"的假晋升。

**(3) 效用信号对正确性结构性失明。** 幻觉事实与正确事实同样相关、新颖、近期，A-MAC 式效用打分无法区分二者；正确性（源上下文支持度）是不可替代的独立准入维度（ConsistencyGate）。

**(4) 组合式与触发式污染。** MemPoison 证明：L2（恶意/错误 payload 拆成多条单独看均合理、联合检索时才显现）与 L3（休眠条目遇特定触发上下文才激活）在结构上绕过写时检查——写时防御只能可靠抑制 L1。

**(5) 保守性与效用的权衡。** GovMem 真实 trace 评测中依赖感知准入把假晋升从 0.371 降到 0.032，但代价是召回仅 0.448、复核负担 0.692；对外部 133 条高影响候选的人工终审中 **0 条**可自动晋升。准入机制必须在"漏放坏经验"与"饿死记忆库"之间显式选点。

### 5.2 判别侧准入管线（候选提取→多信号评分→三值裁定→写入/归档/人审）

**Step 1 候选提取与溯源。** 每个候选记忆由 proposer 从 trace 归一化生成，强制附带溯源元数据：来源 trace/event 引用、Builder 身份与信任级、prompt 族/工具链/父事件（依赖判定用）、作用域字段（task/repo/version/环境/前置条件）、反例引用（GovMem）。

**Step 2 多信号评分（Moderator 侧，独立于 Builder）。**
- **证据支持分**：对候选 m 用判别 LLM 对源上下文做 K=5 次软评分（0–1），均值 ≥ τ=0.7 才通过；无法调参时用随记忆占用率自适应的阈值调度；结构化上下文可用单次 log-prob 变体（12–14× 加速）（ConsistencyGate）。
- **依赖感知支持度**：按溯源依赖分组计票——共享 prompt、共享工具、复制关系、同一父事件的观察只算一票；要求 ≥2 条**独立**证据线（不同 Builder 或不同任务、不同工具链）（GovMem）。
- **效用与类型先验**：A-MAC 五因子（未来效用/事实置信/新颖性/近度/内容类型先验）；类型先验用于硬排除 boilerplate、任务本地叙述、文件 dump、pytest 输出等——GovMem 中 11 条通过验证门控的候选全部因属此类被人工否决。
- **显著性三因子**：来源信誉（Builder 历史正确率）、新颖性（1−与现有活跃记忆最大余弦相似度）、来源可靠级（是否经独立复核）（Selective Memory）。

**Step 3 三值裁定规则（可直接采用）：**
- **Promote（写入 TEAM_MEMORY）**：依赖感知有效支持 ≥2 独立 且 支持分均值 ≥0.7 且 反证检索无强反例 且 作用域明确 且 不在类型排除清单。写入时按**最窄安全作用域**标注（先 task/repo 级，跨项目晋升需额外证据）。
- **Archive（归档冷存储，不删）**：支持不足或过期但未证伪者——保留版本链与取代链接，供日后时间性查询与翻案。
- **Needs-review（人审队列）**：其余一切情形。**fail-closed：任何未决候选一律不进 TEAM_MEMORY**（Memgar）。Spec 级（L2）条款一律走人审，不设自动晋升通道——这是 GovMem"0/133 可自动晋升"给出的直接教训。

**Step 4 信任生命周期。** 每条记忆带信任分，按时间衰减（Memgar 采用 180 天衰减周期）；被后续任务再次验证则 reinforce 重置衰减时钟；连续被反证命中则降信任直至归档。

### 5.3 防坏经验污染的分层防御

- **写入时**：临时 Builder 默认低信任级（源隔离）；溯源依赖计票防回声放大；反证检索+作用域相容性检查防过度泛化；类型排除清单；fail-closed。
- **检索时**：信任感知检索——低信任/过期/跨作用域条目在注入上下文前被过滤或标记；意图感知过滤（MIND 思路）；对低信任命中附加"未经验证"标注，让下游 agent 知情使用。
- **存储后**：(a) 完整性快照+校验+回滚、周期审计与篡改检测（Memgar）；(b) 矛盾取代：新证据冲突时把旧条目标记为非活跃而非覆盖（MemClaw）；(c) **回归门控复审**：已沉淀规则只有在"不破坏任何已通过任务且至少修复一个失败任务"时才保留；(d) 针对 MemPoison L2/L3 盲区，引入 MID 式反事实归因——定期把坏输出反事实地移除候选记忆做影响分解（单条影响、成对交互、触发激活），定位组合致害条目。

### 5.4 值得采用的论文/项目

| 来源 | 借鉴点 |
|---|---|
| GovMem（arXiv:2607.02579） | promote/reject/needs-review 三值裁定、依赖感知计票、溯源标注协议、保守性基线 |
| ConsistencyGate（arXiv:2607.22962） | K=5/τ=0.7 自一致性支持分、自适应阈值、log-prob 快速变体、"正确性≠效用"准入维度 |
| Selective Memory（arXiv:2603.15994） | 写时门控优于读时过滤的量化证据、显著性三因子、归档不删除+版本链 |
| A-MAC（arXiv:2603.04549） | 五因子结构化准入、内容类型先验 |
| SSGM（arXiv:2603.11768） | 固化前一致性验证+时间衰减+访问控制三道关卡 |
| MemPoison（arXiv:2607.14651） | L1/L2/L3 威胁阶梯、写时防御盲区、MID 归因方法 |
| Memory Poisoning Defense（arXiv:2601.05504） | 复合信任评分、信任感知检索+时间衰减、阈值需精调的教训 |
| Memgar（github.com/slcxtor/memgar） | fail-closed 多层检测、信任衰减与 reinforce、人审写网关、快照回滚、框架集成 |

### 5.5 局限性与开放问题

- **自动晋升上限很低**：GovMem 对外部高影响候选 0/133 放行，说明早期实际是"人审为主"；Swarm 需接受较高复核负担，或限定自动晋升只作用于低影响、窄作用域条目。
- **写时防御存在结构性盲区**：L2/L3 目前无经充分验证的防御方案，只能靠检索时与存储后机制缓解。
- **阈值敏感**：信任阈值过严会拒一切、过松会漏攻击，需按部署校准；τ、支持度门槛、衰减率都应做消融。
- **判别者独立性**：Moderator 与 Builder 同模型族时共享偏差，程序独立不等于证据独立。
- **缺 coding-swarm 专用评测**：可用 GateMem、GovMem-Bench、MemPoison-Bench 拼装基准。

### 5.6 关键结论

1. **写时准入是主防线**：读时过滤在高干扰比下崩溃，污染会级联放大，准入必须由独立于 Builder 的判别侧（Spec Moderator）在写入时裁定。
2. **计票必须依赖感知**：支持度按溯源独立性计算而非出现次数，是防"临时 Builder 偶然选择被回声放大"的核心机制。
3. **裁定用三值而非二值**：fail-closed 地把一切未决候选推入归档/人审，宁缺毋滥；Spec 级条款不设自动晋升。
4. **防污染必须分层**：写时门控只解决 L1；组合/触发式污染需检索时信任过滤 + 存储后审计、取代、回归复审与反事实归因共同兜底。
5. **记忆要带生命周期**：作用域标注、信任衰减、验证续期、版本链归档，使每条团队记忆始终"可追溯、可降级、可回滚"。

## 六、建议三：Swarm 架构与团队记忆治理（整体架构视角）

### 6.1 架构挑战

- **多实例并发写入与矛盾持久化**：并行 Builder 各自产出"经验候选"，若直接 append，将出现陈旧传播与矛盾持久化。MemClaw 将 fleet-memory 形式化为 F=(A,M,G,P,T)，并归纳四类失败模式：未授权泄漏、陈旧传播、矛盾持久化、来源崩塌。
- **共享作用域**：并非所有记忆对所有 agent 可见。MemClaw 实测发现租户隔离完好、但 GET-by-id 直读路径曾绕过子租户作用域，说明作用域强制必须在每条读写路径上落实而非仅靠默认检索路径。
- **角色分工与裁定权**：临时 Builder 的偶然选择不该直接进入长期先验；需要与执行解耦的判别角色。INMS 证明"专用 LLM scorer 按 rubric 评分、阈值门控写入"的共享记忆池有效；Conclave 796 次基准实验显示结构化方法学带来 +10–12pp 提升且"结构重于模型能力"，支持把经验外化到 Spec/技能而非依赖单次执行。

### 6.2 团队共享记忆的分层架构与治理原语

采用四层架构：**agent 本地记忆**（实例草稿区，无传播权）→ **团队共享记忆 TEAM_MEMORY**（经裁定的条目）→ **归档记忆**（被取代/被拒条目，留作审计与回滚）→ **项目延续记忆**（constitution/Spec，跨任务身份）。治理原语：

- **作用域**：每条片段标注可见域（实例/团队/全局）与读写权限，权限可时变，用用户-agent-资源关系显式编码（Collaborative Memory）；
- **时间取代**：矛盾写入不删除旧条目，而是标记为非活跃并保留版本链，读端默认只见当前活跃版本（MemClaw）；
- **来源追踪**：每条片段携带不可变来源属性（写入者、源 trace/commit、时间戳），支持事后权限校验、审计与坏经验召回（Collaborative Memory）；
- **策略化传播**：条目从本地升格为共享须经传播策略裁定（谁有权 promote、传播到哪个作用域），而非自动同步（MemClaw）。

### 6.3 Spec Moderator 的角色设计与裁定协议

Moderator 是与执行层解耦的独立角色，兼任守门人（写入门禁）、仲裁者（矛盾裁定）、策展人（沉淀后维护）。建议协议五步：

1. **候选提案**：执行实例以结构化标记（如 Conclave 公告板的 BUS:discovery / warning / intent 格式）产出经验候选，强制附证据（trace、测试、commit）。
2. **评分门控**：独立评审按 rubric 打分，阈值准入（INMS 的 scorer；A-MAC 五因子、GovMem 三态可作打分框架）。
3. **共识分级**：多评审"全员一致→高优先级、多数→中等、单一→仅记录"，关键问题阻断（Conclave）。注意多数共识≠正确，存在规模上限且可能放大坏经验（Majority-Following 反例），裁定依据应是证据+来源信誉而非票数。
4. **选择体制分层**：四种体制（无治理/宪法式混合/自动指标/人工批准）是设计选择而非优劣排序。建议按影响面分级：实现约定（L3）走自动指标+评审共识；Spec 条款（L2）走共识+抽检；constitution 级（L1）强制人工批准。
5. **Fail-closed 与审计**：不确定即拒绝并留痕可回滚（Memgar 做法）。

一个关键工程陷阱来自 MemClaw 实测：同步近重复去重门会抢在异步矛盾检测器之前拒掉"矛盾但正确"的写入——去重与矛盾裁定必须有序协调，且一致性成本应支付在写时而非读时。

### 6.4 Spec 工件链作为经验沉淀载体

将 spec-kit 工件链 constitution → specify → clarify → plan → tasks → implement 做成**双向链**：正向自上而下约束执行；反向经验自下而上晋升——被验证的实现约定写入 plan/tasks 模板或 AGENTS.md 类约定（L3），跨项目规范升为 spec 条款（L2），价值原则升为 constitution（L1）。每次晋升以类 PR 的受审变更落地，天然继承版本控制、评审、回滚；`/speckit.analyze`（跨工件一致性分析）与 `/speckit.checklist` 充当防污染回归门。

### 6.5 值得采用的论文/项目

| 来源 | 借鉴点 |
|---|---|
| Governed Shared Memory / MemClaw（arXiv:2606.24535） | 四类失败模式清单；作用域/时间取代/来源/传播四原语；管道排序教训 |
| Governed Collaborative Memory as Artificial Selection（arXiv:2605.04264） | 选择体制四分类；四层记忆架构；以"来源保真、选择可追溯、认知质量、纠错通道、角色保持"评价记忆 |
| Collaborative Memory（arXiv:2505.18279） | 私有/共享双层；不可变来源属性；读/写策略与可证明合规 |
| INMS（arXiv:2404.09982） | rubric 评分门控写入；可调优检索中介缓解回声室 |
| Conclave | 共识分级裁定+阻断；消息总线/公告板跨波次累积项目知识 |
| GitHub Spec Kit | SDD 工件链、constitution、analyze/checklist 一致性门 |
| LangGraph | 图驱动状态化编排+持久记忆 store，作为 Moderator 管线的执行底座 |
| GateMem（arXiv:2606.18829） | 访问控制/主动遗忘/长程效用的联合评测维度 |

### 6.6 局限性与开放问题

- **评测缺口**：尚无公开基准端到端评测"执行→Spec 沉淀"闭环；GATEMEM 仅覆盖记忆治理维度。
- **判别方可被污染**：Moderator 本身面临注入与"貌似合理的坏经验"欺骗；必须叠加来源追踪、作用域与事后审计。
- **裁定成本-时效权衡**：人工批准可靠但慢，自动指标快但易被利用，动态分级体制缺乏定量调参依据。
- **回声室与漂移**：共享记忆可能放大同质错误，需检索中介与 drift-aware 维护持续纠偏。
- **作用域强制脆弱性**：直读路径绕过作用域的事故表明需对治理层做持续实测而非仅靠设计推演。

### 6.7 关键结论

1. 团队记忆应被视为**受治理的分布式系统**而非检索索引：作用域、时间取代、来源追踪、策略化传播是一等原语。
2. **写时裁定优于读时过滤**：Moderator 以 promote/reject/needs-review 三态裁决，人工批准仅保留给 constitution 级高影响条目。
3. **共识≠正确**：采用分级共识+证据裁定+关键问题阻断，杜绝简单多数放大坏经验。
4. **Spec 工件链应双向化**：constitution→tasks 链既约束执行，又是经验晋升的可审计载体与回归门。
5. **沉淀不是一次性写入**：选择体制必须包含归档、取代、召回与周期维护，使"选择本身可检查"。

## 七、综合建议：总体机制蓝图

综合三个方向的建议，一个符合原始问题全部硬性要求的机制由五个阶段组成，前四阶段构成"学习→沉淀"主链路，第五阶段提供长期防腐：

```
执行实例(代码) → ① 提取与归因 → ② 形式化(L2/L3分流) → ③ 判别侧准入(Spec Moderator)
             → ④ 沉淀到 Spec/TEAM_MEMORY → ⑤ 持续维护与防污染(剪枝/取代/审计/回滚)
```

### 7.1 各阶段的机制选型

| 阶段 | 推荐机制 | 主要来源 |
|------|---------|---------|
| ① 提取与归因 | 失败签名聚类 + 首错步骤归因 + 多轨迹命中阈值（≥2 独立） | Self-Harness、SkillAdaptor、GovMem |
| ② 形式化 | 双形态条款（NL+符号字段）；可机器判定的进 L2 谓词条款，执行性的进 L3 约定 | RIMRULE、AutoSpec、SpecGen |
| ③ 判别侧准入 | 独立 Moderator：支持度 K=5/τ=0.7 + 依赖感知计票 + 类型先验排除 + 三值裁定 + fail-closed；L2 一律人审 | ConsistencyGate、GovMem、A-MAC、Memgar |
| ④ 沉淀 | 四层记忆架构 + 治理四原语（作用域/时间取代/来源追踪/策略化传播）；Spec 工件链双向晋升（类 PR 受审变更） | MemClaw、Artificial Selection、spec-kit、LangGraph |
| ⑤ 维护与防腐 | 回归门控复审（≥1 修复 ∧ 0 回归）、MDL 剪枝、CEGIS 反例演化、信任衰减+验证续期、快照审计+回滚 | harness-loop、RIMRULE、AutoSpec、Memgar、SKILL-KD |

### 7.2 关键参数速查（均可从论文中直接取用）

| 参数 | 建议值 | 来源 |
|------|--------|------|
| 支持度采样次数 K | 5 | ConsistencyGate |
| 支持度准入阈值 τ | 0.7（结构化场景可用 log-prob 单次变体） | ConsistencyGate |
| 独立证据线要求 | ≥2 条（按溯源依赖去相关后） | GovMem |
| 接受条件 | ≥1 原失败转通过 ∧ 0 已通过回归失败 ∧ 留出集不降 | harness-loop / Self-Harness |
| 信任衰减周期 | 180 天，验证后重置 | Memgar |
| 三值裁定 | promote / archive(归档不删) / needs-review；未决一律不写入 | GovMem + Selective Memory |
| 选择体制分级 | L3 自动指标+共识；L2 共识+抽检+人审；constitution 级强制人审 | Artificial Selection |

### 7.3 实施优先级建议

1. **第一步（最小闭环）**：以 harness-loop 的 run→mine→gate→inject 为骨架，叠加 SkillAdaptor 式首错步骤归因，即可获得"学习+沉淀+防污染"的最小可用系统。
2. **第二步（判别侧）**：引入独立 Moderator 服务（参考 Memgar 的 write gateway + ConsistencyGate 支持分 + GovMem 三值裁定），把所有写入纳入 fail-closed 管线。
3. **第三步（团队化）**：用 LangGraph Store+namespace 或 Letta 的 git 并发写承载 TEAM_MEMORY，叠加 MemClaw 四治理原语与 spec-kit 工件链作为 Spec 载体。
4. **第四步（长期治理）**：接入回归门控复审、MDL 剪枝、信任衰减与快照回滚，定期做 MemPoison 式 L2/L3 反事实审计。

### 7.4 最重要的五条总体判断

1. **写时裁定是不可妥协的主防线**：读时过滤在 8:1 噪声下崩溃（Selective Memory），污染随轨迹级联放大（ConsistencyGate），因此"记忆写入须由判别侧裁定"必须落在写入时点。
2. **重复不等于证据**：Swarm 特有的陷阱是相关证据被当成独立支持（GovMem），临时 Builder 的偶然选择会经复制/引用获得虚假高支持度，依赖感知计票是针对性解法。
3. **归因是防污染的第一道闸**：失败信号必须钉到具体步骤/条款/技能（Self-Harness、SkillAdaptor、SKILL-KD），否则整条轨迹的失败会污染整个记忆库。
4. **验证硬度决定形式化层级**：能编译/执行为可检验断言的（契约、lint、测试）走 L2 硬准入（Spec-Agent 零假阳性范式），执行性约定走 L3 回归门控（Self-Harness 范式）。
5. **治理即学习**：沉淀机制本身要能被审计、回滚与演化（不可变账本、版本链、周期对账），否则团队记忆会随时间退化为误报与坏先验的来源（SSGM、AutoRefine、AutoSpec）。
