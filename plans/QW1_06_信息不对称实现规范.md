# 06 信息不对称实现规范

> PDR-001 §7：信息不对称是硬约束，不是礼仪。本文给出四层落地：存储、访问控制、注入点、反馈降维。
> 参考实现：swarm_kernel/bus（ACL + 审计 + 篡改检测，tests/communication 11 用例全绿）。

## 1. 威胁模型

reward hacking 的信息前提 = builder 能看到判据。消除前提即消除该类攻击面：
- View(builder) ∩ View(verifier 判据) ⊆ 公开集（spec L1/L2/L3 + 接口面 + 自测框架）。
- 生成者不参与判别；judge 不评审自身参与生成的实例；判别侧 session 内冻结。

## 2. 存储隔离

| 资产 | 存放 | builder 可见性 |
|---|---|---|
| spec（L1/L2/L3） | spec/spec.json | 可见（全量） |
| 接口冻结面 | WavePlan.frozen_interfaces | 可见 |
| holdout 场景库 | oracle/scenarios/ | **deny** |
| 差分语料生成器 | oracle/corpus.py | **deny** |
| rubric | oracle/rubrics/ | **deny** |
| 黄金输出 | oracle/golden/ | **deny** |
| mock 场景集 | mock/（builder 自测用） | 可见 |
| 判词逐样本明细 | judge 侧 | **deny**（builder 只见聚合） |

落地手段（T7）：
1. 文件系统：builder 沙箱（jiuwenbox）挂载策略对 oracle 目录整体 deny；rail 级二次拦截（读路径前缀匹配 → Guardrail HIGH → AbortError）。
2. 工具白名单：builder 无 oracle 检索工具；cartographer 为 builder 提供的定位服务同样过滤 oracle 路径（返回"不可见"而非内容）。
3. 进程级：holdout 只注入 verifier workflow 的执行上下文（独立 context_id），不进任何共享记忆。

## 3. 注入点与中继（编排器净化）

- builder → 编排器：仅 InstanceSubmission（artifact_path + contract_surface_digest + resource_report）。CoT/中间产物留在沙箱内，随临时团队销毁。
- 编排器 → judge：脱敏后的提交摘要（JudgeWorkflow._sanitize 去除 builder_identity/chain_of_thought/timestamps；匿名化开关默认开，测试覆盖）。
- judge → builder：仅聚合结论（通过/否决 + 条款级原因列表）；逐样本判词、位置实验数据留在 judge_internal 保密级。
- 信封封条：所有跨域消息 payload 哈希封条；FileRelay 接收端验封，破损即拒（strict 模式抛 IsolationViolation，测试覆盖）。

## 4. 角色-保密级矩阵（bus default_acl 权威）

| 保密级 | 可读 | 禁读 |
|---|---|---|
| holdout | verifier、architect、system、human | builder 及其他 |
| judge_internal | verifier、architect、system | builder 及其他 |
| memory_restricted | 持久角色 | 临时 builder |
| public | 全员 | — |

生产者约束：
- JudgeVerdict 生产者 ∈ {verifier}（builder 生产被拒投，测试覆盖）。
- MemoryWrite 生产者 ∈ {spec moderator 裁定后}（builder 生产被拒投，测试覆盖）。

## 5. 双流水线隔离（B 标定线）

- 独立 leader、独立记忆域、独立 session 前缀；B 线 builder 同样不见 A 线 holdout（两线 oracle 目录物理分开，B 线用探针场景池）。
- B 线成功定义 = 学到沉默/分歧位置；代码全部丢弃，只产出 spec-delta、oracle 补强、案例记录（账本断言：B 线无 admission 记录）。

## 6. 审计与问责

- bus 审计日志记录每次投递与拒绝（subscriber、原因）；拒绝事件入 EventLog(kind=isolation_denial)。
- 每周健康度报告包含 isolation_denial 计数；非零值必须逐条归因（测试残留或真实越权）。
- 会话/沙箱隔离检查列入 M1 门槛（08 文档）。

## 7. 已知边界与显式代价

1. 本地单机部署下"deny"依赖沙箱与纪律双重保障；TEE/机密飞地方案（研究建议）评估后**暂不采纳**（小团队收益/成本不划算），保留 KMS+审计作为 M3 备选。
2. 强互不信任场景的 MPC 判官、水印溯源：不采纳（过度设计）。
3. 判官面板（跨厂商多判官）：仅高风险判定启用，默认单判官多采样（成本约束）。
