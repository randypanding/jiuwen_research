## 2. 物理拓扑（local 优先，PDR-001 §11 决定）

```
                    ┌─────────────────────────────────────────────────┐
                    │  leader 持久团队（编排，team.runtime.mode=local）│
                    │  - 波次推进、事件驱动、准入触发                  │
                    └───────┬───────────────────────────┬─────────────┘
                            │ create_task/send_message  │ 事件订阅(MonitorEventType)
        ┌───────────────────┼──────────────────┐        │
        ▼                   ▼                  ▼        ▼
 architect 过程        verifier workflow    spec 侧持久代理   cartographer(agent-as-tool)
 (切波次/DoD/rubric)   (跑H1-H8+judge)     (steward/moderator/reconciler)  (弱档高缓存)
        │                   │
        │ holdout(不可见↓)  │ GateResult/ScenarioOutcome
        ▼                   ▼
 临时 builder 团队 ×N（lifecycle=temporary，无记忆写，沙箱内）
        │ InstanceSubmission（仅 claim+证据，无 CoT）
        ▼
 准入事务（swarm_kernel.admission）→ world/ + EVIDENCE.json + 账本
```

- 单机：`team.runtime.mode=local`，inprocess transport；分布式（pyzmq+A2X+PG+NFS）M3 之后再评估。
- 每角色独立 context_id（ContextEngine），总线 session_scope 与之一致；跨域订阅必须显式通配并接受审计。

## 3. 关键组件设计（新建件）

### 3.1 spec 仓（T1）
- 物理形态：目标域仓库内 `spec/` 目录 + `spec.json`（SpecDoc 序列化）。条款为 SpecClause：稳定 clause_id、level、r_level、契约体（pre/post/invariant/assume/guarantee）、dont_care、见证引用。
- 条款摘要：canonical JSON → sha256；代码锚点 `# @spec <ID> #<digest16>`（已实现于 swarm_kernel.spec_repo）。
- 变更：SpecDelta（add/modify/remove + BC/NBC）；版本策略：NBC→major、add/modify→minor、remove-only-BC→patch（已实现 versioning.py）。
- 锁与并发：写者为少数（steward/moderator），采用"文件锁 + 提交时摘要校验"即可；不引入 MVCC/分布式锁（研究建议中的 TiKV/Percolator 推迟，见 09 文档）。

### 3.2 oracle 目录（T2/T3）
- `scenarios/*.yaml`：HoldoutScenario（FAIL_TO_PASS / PASS_TO_PASS 两类判分）。
- `corpus.py`：gen_corpus(seed,n) 差分语料生成器（oracle 私有）。
- `baseline_contract.json`：契约面基线（H4 破坏性变更检测用）。
- `golden/`：R3 黄金输出 + manifest（批准人必填）。
- ACL：整个目录对 builder 身份 deny；verifier/architect 可读。

### 3.3 门禁 runner（T2）
- 参考实现 swarm_kernel.gates；生产化封装为 CLI/WorkflowAgent 节点：
  `swarm-kernel gates run --instance D --oracle O --spec S --out OUT --group G...`
- 退出码：0 pass / 1 fail / 2 inconclusive（含未配置、缺件、error）。
- flaky：命令类门禁默认单次尝试（确定性假设）；标注 flaky 的套件启用重试 + Wilson 三判定（pass_threshold=0.4 / fail_threshold=0.6，n=1 按点估计）；inconclusive 进隔离区打标，不放行不误杀。

### 3.4 准入事务（T4）
- staging → world 原子提交（临时目录 + rename）；账本 JSONL 哈希链；preimage 留存支持回滚；EVIDENCE.json 随实例入库。
- PR 重定义：PR = 准入事务 + 证据收据（EvidenceReceipt：delta 引用、R 级、选中/丢弃实例及测量结论、H1–H8、judge 判词、差分结论、漂移检查）。人类只在 R2/R3 或 L2 diff 时介入。

### 3.5 测量与收敛（T6/T8）
- N 份实例的套件结果 + 差分报告 → MeasurementEvent 六分类（closed/silence/divergence/tier_upgrade/conflict/insufficient_samples），处置路由固定（已实现 pipeline.run_fanout_pipeline）：
  - closed → 选实例准入（次级判据：字典序最小名，确定性）
  - silence → 冻结准入，spec moderator 登记 don't-care 或补条款后重测
  - divergence → spec moderator 收敛 spec，oracle 不动
  - tier_upgrade → 升档重采样（≤2 次）
  - conflict → 升级规范级事件（steward+architect 会诊）
  - insufficient_samples → 补生成至 ≥3

### 3.6 漂移检测 H7（T6）
- 锚点哈希漏斗：①摘要比对（stale/orphan/unimplemented）→ 硬阻断；②豁免台账（带过期审计）；③（M2+）LLM 语义复核只跑可疑切片、夜间批扫。
- 起步基线全部只告警积累精度，M1 起对收割域转强制（08 文档门槛）。

## 4. 与 Studio 的边界

- Studio 的中央路由多智能体不作为 swarm 内核（PDR-001 §11）。
- Studio 可复用点：工作流 IR 可视化（门禁流水线展示）、版本-渠道机制（发布回滚参照）。均为可选项，不进入 M0–M2 关键路径。

## 5. 依赖与版本锁定

- openjiuwen 各仓以本仓库 submodule 指针为准（见 CAPABILITY_MAP.md 顶部表）；swarm-kernel 不直接依赖 openjiuwen 包（零耦合参考实现），T7/T8 集成层（jiuwenswarm harness）依赖 `openjiuwen @ git+...agent-core.git@<submodule SHA>`。
- Python ≥3.11；swarm-kernel 运行依赖仅 pydantic≥2.7 + pyyaml（测试加 pytest）。
