# 02 契约规范（唯一权威：swarm-kernel/contracts）

> 契约即团队边界。跨团队交互只允许使用本文列出的契约消息；字段增删 = 规则变更提案。
> 权威实现：`swarm-kernel/swarm_kernel/contracts/`（31 个模型，tests/contract 全量覆盖）。

## 1. 信封与传输

`ContractEnvelope`（base.py）：
- 字段：envelope_id、schema_name、schema_version、producer_role、consumer_role?、topic、session_scope、confidentiality、ts、payload、payload_sha256。
- 封条：`seal()` 计算 payload 的 canonical sha256；接收方 `verify_seal()`，破损即拒收（通信测试已覆盖篡改检测）。
- 传输：进程内 ContractBus（pub/sub + ACL + 审计）；跨进程 FileRelay（NDJSON，topic→文件）。
- session_scope 必须等于订阅方域，或订阅方显式 `*`（仅 reconciler/观测类允许）。

## 2. 保密级与 ACL 矩阵（default_acl，bus/bus.py）

保密级：public / holdout / judge_internal / memory_restricted。

| 消息 | 生产者 | 可见消费者 | 禁止可见 |
|---|---|---|---|
| HoldoutScenario / Rubric | architect | verifier、architect | **builder**（任何生成者） |
| JudgeVerdict | verifier | leader、architect | builder 不得生产；builder 消费仅限聚合结论（降维后） |
| MemoryWrite | spec moderator（裁定后） | steward | **builder 直接生产被拒** |
| TeamMemoryDigest(memory_restricted) | spec moderator | 持久角色 | 临时 builder |
| FanoutRequest / InstanceSubmission / GateResult / MeasurementEvent / WavePlan / SpecDelta / EvidenceReceipt / AdmissionDecision / DriftEvent / RuleProposal / HealthSnapshot | 见角色表 | public | — |

硬规则（ACL 内置，测试覆盖）：
1. builder 收不到 holdout / judge_internal / memory_restricted。
2. builder 生产的 JudgeVerdict 一律拒投（生成者不得参与判别）。
3. builder 生产的 MemoryWrite 一律拒投（可丢弃主体不写长期记忆）。
4. 拒绝事件全部落审计日志（AuditRecord）。

## 3. 契约清单

### 3.1 spec 域（spec.py）
| 契约 | 关键字段 | 约束 |
|---|---|---|
| SpecClause | clause_id、level(L1/L2/L3)、r_level、text、contract_body(pre/post/invariant/assume/guarantee)、dont_care[]、witness_kind/refs、status、version | digest=canonical sha256；anchor=`@spec ID #digest16`；无见证的 active 条款=unverifiable，只能作 advisory |
| DontCareDeclaration | kind(output_freedom/unreachable_state/ignorable_output)、scope、registered_by | 只允许 spec moderator 登记 |
| SpecDoc | spec_id、spec_version、clauses[] | 真值载体 |
| SpecDelta | delta_id、base/new_spec_version、changes[](add/modify/remove + BC/NBC) | 含 NBC → requires_human_approval=True |

### 3.2 波次与 fan-out（wave.py、fanout.py）
| 契约 | 关键字段 | 约束 |
|---|---|---|
| WavePlan | wave_id、epoch、delta_ids、frozen_interfaces[](接口摘要)、stage | 波次=接口冻结窗口+事务边界 |
| FanoutRequest | fanout_id、wave_id、delta_id、r_level、n_instances、seed | **R3 强制 n=1**；n∈[1,8] 硬顶 |
| InstanceSubmission | instance_id、fanout_id、artifact_path、contract_surface_digest、resource_report | 只含 claim+证据引用，不含 CoT（judge 前再做一次脱敏） |
| MeasurementEvent | 六分类 + pass/fail 计数 + divergence_inputs | 分类规则见 measure/engine.py，不得旁路 |

### 3.3 门禁与判据（gates.py、oracle.py）
| 契约 | 关键字段 | 约束 |
|---|---|---|
| GateResult | gate_id(H1..H8)、verdict(pass/fail/inconclusive/error)、attempts、witness_refs[]、details | 每个结论必须附机械见证或明示 inconclusive 原因 |
| GateSuiteResult | instance_id、results[] | hard_pass = 8 门全 PASS；inconclusive/error/缺门均不算过 |
| HoldoutScenario | scenario_id、inputs、expectation、grading(FAIL_TO_PASS/PASS_TO_PASS) | confidentiality=holdout |
| Rubric / RubricItem / BiasControls | items[](criterion+weight+evidence_required)、bias(samples≥1、position_swap、anonymize、abstain_on_disagreement、min_calibration_kappa) | judge 侧私有 |
| JudgeVerdict | kind(veto/no_veto/abstain)、reasons、citations[]、samples_used | **无豁免字段**（schema 层禁止）；veto 无证据引用自动降级 abstain |

### 3.4 准入域（admission.py）
| 契约 | 关键字段 | 约束 |
|---|---|---|
| EvidenceReceipt | wave/delta、r_level、chosen_instance、discarded[]（含测量结论）、gate_suite、judge_verdict?、drift_check、prior_receipt_sha256 | complete = 硬门全过 ∧ 漂移干净 |
| AdmissionDecision | admit、reasons、transaction_id、rollback_handle | admit 必附回滚句柄 |
| LedgerEntry | tx、receipt_sha256、prior_entry_sha256、entry_sha256 | 哈希链；篡改可检（测试覆盖） |

### 3.5 治理域（drift.py、evolution.py、health.py）
| 契约 | 关键字段 | 约束 |
|---|---|---|
| DriftEvent / AnchorRecord | state(ok/stale/orphan/unimplemented)、severity | stale/orphan/unimplemented=阻断 |
| RuleProposal | case_refs、rule_text、scope、status、effective_session | **may_apply_current_session 恒 False**；生效必须指定未来 session |
| HealthSnapshot | closure_rate、spec_entropy_events_per_delta、witness_coverage、unverifiable_clauses、escape_defect_rate、drift_alert_rate、judge_kappa、judge_abstention_rate、rework_rate、admission_cost_tokens、stage(M0-M3) | 人类报告面只含这些 + L1/L2 事项 |

## 4. 实例打包契约（builder 交付物，H 门禁输入）

```
<instance_dir>/
  swarm_entry.py    # 适配器：def run(inputs: dict) -> Any；局部模块由门禁加载器 fresh-load
  contract.json     # {"exports": [...], "signatures": {...}, "dependencies": [{"name","license"}]}
  report.json       # {"tokens": float, "seconds": float, "bytes": float}
  tests/            # builder 自测（H2）；不是 holdout
  <实现文件>         # L1/L2 条款锚点注释：# @spec REQ-XXX #<digest16>
```

缺失规则：无 swarm_entry.py → H3/H5 error；无 contract.json → H4 fail；无 report.json → H8 inconclusive；无锚点 → H7 unimplemented（L1/L2）。

## 5. 契约版本化规则

1. 每个契约模型带 contract_version（整数）；信封 schema_version 同步。
2. 加字段（可选）= BC；改语义/删字段 = NBC → 需 RuleProposal 人类批准，且消费方双版本兼容期 ≥1 个波次。
3. JSON Schema 导出作为跨语言消费凭据（`ContractModel.model_json_schema()`），测试 tests/contract 已对全部 31 模型做 schema 校验。
